# pixel·folio

Портфолио пиксель-арта, которое собирает и раскладывает само себя. Всё, что
нужно делать художнику — кидать `.png`/`.gif` в папку `/works` и пушить в
`main`. Дальше отрабатывает GitHub Actions: анализирует картинки, строит
`manifest.json`, собирает статику и деплоит на GitHub Pages.

## Как добавить работу

1. Положи файл в `/works` (только `.png` или `.gif`).
2. Закоммить и запушь в `main`.
3. GitHub Actions сам пересчитает раскладку и выкатит обновлённый сайт.

Никаких конфигов трогать не нужно — имя файла, дата и размеры карточки
выводятся автоматически.

## Как работает раскладка

`scripts/generate-manifest.mjs` при каждом запуске сканирует `/works`,
читает реальные размеры каждой картинки и решает, сколько клеток сетки
она займёт, по соотношению сторон (`ratio = width / height`):

| ratio            | размер карточки |
|-------------------|------------------|
| ≥ 2.4              | 3×1 (очень широкая) |
| ≥ 1.6              | 2×1 (широкая)        |
| ≤ 0.6              | 1×2 (высокая)        |
| 0.85–1.15 и картинка крупная (≥ ~1000×1000px) | 2×2 («хиро»-карточка) |
| всё остальное      | 1×1 (квадрат)         |

Раскладка детерминированная: пока сама картинка не изменится, она всегда
получит один и тот же `gridSpan`. Порядок карточек — по дате добавления
файла в git (свежие сверху), при совпадении дат — по имени файла.

Заголовок карточки выводится из имени файла: `piece-01.png` → «Piece 01».

## Локальный просмотр

```bash
npm install
npm run generate-manifest
python3 -m http.server 8000
```

Открыть `http://localhost:8000`.

## Деплой: как это устроено

В `manifest.json` в репозитории лежит placeholder (`[]`), актуальный список
работ пересчитывается на каждом запуске workflow — вот два варианта, как
это можно было бы сделать, и почему выбран второй:

- **Коммит бота.** Workflow пересчитывает `manifest.json` и коммитит его
  обратно в `main` от имени бота, если файл изменился. Плюс — файл в
  репозитории всегда актуален и виден в истории. Минус — лишние коммиты,
  риск гонки при параллельных пушах, нужны права на запись в ветку.
- **Артефакт без коммита (выбран).** Workflow пересчитывает `manifest.json`
  только внутри job'а, кладёт его вместе со статикой в артефакт для
  GitHub Pages и никогда не пишет обратно в git. Проще в поддержке, не
  плодит коммиты, не требует повышенных прав — `contents: read` достаточно.
  Единственный компромисс: файл `manifest.json` в самом репозитории не
  отражает актуальный список работ (это норма, он там только как заглушка
  для локальной разработки).

## Включить GitHub Pages

Settings → Pages → Source → **GitHub Actions**. После первого пуша в
`main` сайт появится по адресу вида `https://<user>.github.io/<repo>/`.

## Структура

```
/works/                      PNG/GIF работы — единственное, что трогает художник
/scripts/generate-manifest.mjs   считает размеры и пишет manifest.json
/manifest.json                заглушка для локального просмотра
/index.html, style.css, script.js   статический фронтенд без сборки
/.github/workflows/build-deploy.yml   пересчёт манифеста + деплой на Pages
```
